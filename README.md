# 大富翁中国之旅 3007 · 桌游银行

移动端优先的实体桌游辅助器。替代纸币、地产证、骰子与记账，不包含地图移动、角色或 AI。

## 启动

需要 Node.js 20.19+（推荐 Node.js 22 LTS）和 npm。

```sh
npm ci
npm run dev
```

打开 `http://localhost:3000`。前后端共用一个端口，不需要另启数据库或配置外部账号。

生产运行：

```sh
npm run build
npm start
```

构建同时执行 TypeScript 检查、Vite 前端打包和 esbuild 服务端打包。生产静态资源与 Socket.IO 同源。

## 围桌联机

1. 所有设备连接同一 Wi-Fi。
2. 启动服务器后，在手机上访问 `http://电脑的局域网IP:3000`。Windows 可用 `ipconfig` 查看 IPv4 地址。手机上的 `localhost` 指手机自己。
3. 房主输入昵称创建房间，朋友使用相同网址、6 位房间号和自己的昵称加入。
4. 房主选择 ¥15,000 / ¥20,000，或填写自定义金额后点“设定”。所有玩家加入后开局。
5. 如操作系统提示端口访问，请仅按你的使用场景允许私人网络访问。本文档不自动修改防火墙。

刷新和短暂掉线会恢复原来的玩家身份。身份凭据保存在当前浏览器的 localStorage，服务器仅保存其 SHA-256 摘要。更换设备、清空浏览器数据或主动退出身份后不会自动认领原玩家。开局后拒绝新玩家加入，原玩家仍能重连。

本机模拟两个独立身份，可分别打开 `http://localhost:3000` 和 `http://127.0.0.1:3000`；两个地址连接同一服务器，但浏览器身份存储相互独立。

## 已实现

- 6 位房间号、昵称、初始资金、开局、在线状态和实时房间快照，最多 8 位玩家（含房主）。
- 银行与自己双向支付、自己与其他玩家双向转账，快捷金额、自定义金额、余额变化提示。
- 全部 41 张地产证，按编号排列，可按色组、待售、我的地产、车站、公共事业筛选，支持名称与编号搜索。
- 买地扣款、向银行售地、抵押、含 10% 利息赎回、批量建房/卖房、旅馆、按当前状态自动收租。
- 同色组空地双倍租金、四个车站阶梯租金、公共事业使用最近一次骰子点数合计计费。
- 房主创建房间时选择 1 或 2 个六面骰，默认 1 个；快速动画、全员同步、最近 20 次结果与对应数量的实体骰子录入。设置随房间保存，重开保留；更新前创建的旧房间保留原来的 2 个骰子。
- 最近操作撤销、完整持久化事件日志（界面显示最近 150 条）。
- 所有子页及弹窗顶部显示现金和总额，破产自动清算并同步。
- 创建时选择限时现金赛（默认 60 分钟 / ¥30,000）或生存赛。到达目标立即结算；限时结束按现金最高结算，并列时共同获胜；生存赛最后一名未破产玩家获胜。
- 房主余额纠错、移除玩家、重新开始与结束游戏，重开/结束均需二次确认。结束会注销全员身份并返回创建页。
- SQLite 事务、请求去重、版本冲突检查、服务器重启和客户端断线恢复；全员离线 24 小时后清理房间。

## 地产与规则

`properties.json` 是地产静态数值的唯一来源，原文件未改动。文件中 `purchasePriceInferred: true` 保留，并在地产证上显示“购买价（推定）”。色组编号原样保留，UI 色彩只作为区分，不声称复刻实物印刷颜色。

JSON 没有覆盖的辅助器规则已在“桌游规则约定”中公开：

- 允许带房抵押，保留建筑、停止收租，符合本次要求的验收流程。
- 赎回支付抵押本金和 10% 利息；利息不足一元向上取整。
- 卖房按房屋建筑费的 50% 退款，可一次选择多栋；旅馆先折成 5 栋房屋，再按选择的栋数出售（因此剩余最多 4 栋）。无建筑且未抵押的地产可以按购买价一半售给银行。
- 自有地产可直接建房，不要求集齐色组或均衡建造。
- 产权仍归原玩家的抵押地计入同色组、车站和公共事业的拥有数量，但该抵押地本身不能收租。
- 总额 = 现金 + 未抵押地产的抵押价格 + 全部建筑的售卖价值（旅馆按 5 栋房屋折算）。已抵押土地不重复计价，其保留建筑仍按可售价值计入。
- 租金/转账债务大于付款人总额时，自动将全部总额支付给债权人、全部地产与建筑归银行、标记破产退出操作；该清算可以撤销。现金不足但总额足够时，先提示卖房或抵押再支付。购买/建房等主动消费余额不足会拒绝。
- 金额为整数，余额上限为十亿元。
- 为支持实体围桌快速记账，玩家可以代扣其他玩家向自己的付款，所有人均可看到事件记录。这是朋友间的桌游辅助器权限模型。
- 操作者或房主可以撤销最近一个可撤销操作；不支持连续回退。加入、踢人、设置初始资金、开局和重开会清除撤销机会。
- 移除玩家会回收其地产、清空这些地产上的建筑与抵押，并使其身份凭据失效。重开保留当前玩家与日志，重置余额、地产与骰子。移除、重开与结束均有界面确认。结束后的房间不可恢复；自然决出赢家后仍可查看记录或由房主重开。

## 数据与并发

类型定义位于 `shared/types.ts`：`Room`、`Player`、`PropertyDefinition`、`PropertyState`、`Transaction`、`GameEvent`、`DiceRoll`。静态定义与动态房间产权分离，前后端共用纯租金计算函数，最终计费仍由服务器计算。

- `server/engine.ts`：权限和规则校验、资金流、产权变更、撤销快照与事件生成。
- `server/store.ts`：SQLite 存储，包含 `rooms`、`sessions`、`events`、`requests` 表，启用 WAL 和外键。
- `server/index.ts`：Socket.IO 入口、Zod 入参校验、身份验证、速率限制、广播和清理。
- `shared/rules.ts`：直接引用原始 JSON，提供租金计算和展示辅助函数。
- `src/App.tsx`、`src/styles.css`：房间、银行、地产、骰子、记录、管理和响应式页面。
- `src/socket.ts`：跨 UI 热更新复用连接。

每个写操作在 `BEGIN IMMEDIATE` 事务中读房间、校验版本、执行规则、写房间快照、写事件和请求 ID，成功提交后广播。失败不会提交部分扣款或产权变更。客户端不能提交任意房间状态；收到旧版本请求时服务器会拒绝并提示确认最新状态后重试。同一玩家的相同请求 UUID 只生效一次。

默认数据库路径是 `data/game.sqlite`，不是浏览器存储。日志随房间清理而删除。请将整个数据目录放在持久磁盘；备份运行中的数据库可使用 SQLite backup API，或停服后复制整个数据目录。

## 部署

此 MVP 使用单个有状态 Node.js 实例，适合个人服务器、家庭电脑或支持持久磁盘的容器平台。不要在多个实例之间轮流分配房间连接；如需要横向扩容，应另行加入共享广播和分布式房间协调。

```sh
docker compose up -d --build
```

容器公开 3000 端口，数据保存在 `journey-data` 卷，自动重启。也可以直接使用 Node.js 生产启动命令。公网使用时，在反向代理上配置 HTTPS 并允许 `/socket.io/` WebSocket Upgrade。项目无需第三方字体、图片或 API 即可工作。

| 环境变量         | 默认值             | 用途                 |
| ---------------- | ------------------ | -------------------- |
| `PORT`           | `3000`             | 服务监听端口         |
| `DB_PATH`        | `data/game.sqlite` | SQLite 数据文件      |
| `ROOM_TTL_HOURS` | `24`               | 全员离线后的保留时长 |

`GET /api/health` 返回健康状态。Docker 构建阶段安装 Python、make 和 C++ 编译器，便于 SQLite 原生依赖在预编译包不可用时从源码构建；运行镜像不包含这些编译工具。
